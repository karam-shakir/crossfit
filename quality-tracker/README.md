# نظام متابعة وثائق ومتطلبات الجودة — وكالة الكلية للتطوير والجودة

نظام مؤتمت لمتابعة تسليم وثائق الجودة من أقسام كلية الحاسبات (جامعة أم القرى) وفق الجدول الزمني، مع إرسال الرسائل تلقائياً عبر **البريد الإلكتروني** و**Microsoft Teams** و**WhatsApp**، ولوحة متابعة عربية لمراقبة كل شيء والتعديل عند الحاجة.

## ماذا يفعل النظام تلقائياً؟

| الحدث | ما يحدث |
|---|---|
| **بداية العمل** (تاريخ البداية في الإعدادات) | رسالة انطلاق لكل رئيس قسم تتضمن الجدول الزمني الكامل (المراحل، المواعيد، الوثائق، مسؤولية التنفيذ، تعليمات الرفع) |
| **قبل كل موعد تسليم بأسبوعين** | رسالة تذكير لكل رئيس قسم **لم يكمل** تسليم وثائق ذلك الموعد، تحوي قائمة الوثائق الناقصة فقط. رسالة واحدة لكل موعد (لا رسالة لكل وثيقة) |
| **اكتمال تسليم وثائق موعد قبل انتهائه** | رسالة شكر وتقدير تلقائية: "تم الاستلام قبل الموعد، سيتم مراجعة الملفات وفي حال وجود ملاحظات سيتم التواصل معكم" |
| **يوم كل موعد نهائي** | تقرير حالة الأقسام إلى بريد الوكيل |
| اختياري: إشعار استلام لمن أكمل بعد الموعد، وتنبيه تأخر بعد انقضاء الموعد | يُفعَّل من الإعدادات |

رصد التسليم يتم بطريقتين:
1. **يدوياً** من لوحة الحالة: اضغط على خلية (قسم × موعد) وحدد الوثائق المستلمة.
2. **تلقائياً من صندوق البريد (IMAP)**: أي رسالة من بريد رئيس القسم تحتوي رقم الوثيقة (مثل `2-7-1`) أو كلماتها المفتاحية في العنوان أو أسماء المرفقات تُسجَّل كتسليم، ثم تُرسل رسالة الشكر في الدورة التالية.

## التشغيل السريع

```bash
cd quality-tracker
npm install
copy .env.example .env      # (Windows)  أو  cp .env.example .env
# عدّل .env: بيانات SMTP، بريد الوكيل، ADMIN_PASSWORD ... واترك DRY_RUN=true للتجربة
npm start
```

افتح http://localhost:4000 وسجّل الدخول بحساب المدير (`admin` / `ADMIN_PASSWORD`) ثم غيّر كلمة المرور.

> **وضع التجربة (DRY_RUN=true)** هو الافتراضي: النظام يخطط ويسجّل الرسائل في "سجل الرسائل" دون إرسال فعلي. راجع تبويب **المخطط اليوم** لترى ما سيُرسل، وعندما تطمئن ضع `DRY_RUN=false` وأعد التشغيل.

## لوحة المتابعة

- **لوحة الحالة**: مصفوفة الأقسام × المواعيد (ملوّنة)، تسجيل الاستلام، تذكير/شكر/تنبيه فوري.
- **التقارير**: تقرير إنجاز لكل قسم وتقرير إجمالي بهوية جامعة أم القرى، جاهز للطباعة/PDF. ضع شعار الجامعة في `public/logo.png` ليظهر في الترويسة.
- **المخطط اليوم**: معاينة الرسائل التي ستُرسل في الدورة القادمة (نصها الكامل) قبل إرسالها.
- **سجل الرسائل**: كل محاولة إرسال (القناة، الحالة، الخطأ) مع روابط إرسال يدوي عند تعذر الإرسال الآلي.
- **صندوق الوارد**: الرسائل المرصودة من رؤساء الأقسام وتصنيف ما لم يُطابق تلقائياً.
- **الأقسام / الوثائق والجدول الزمني / قوالب الرسائل / الإعدادات / المستخدمون**: للمدير فقط.

### المستخدمون والصلاحيات
| الدور | الصلاحيات |
|---|---|
| مدير النظام | كل شيء (الإعدادات، القوالب، الأقسام، الوثائق، المستخدمون، الإرسال) |
| متابع | تسجيل الاستلام، الإرسال اليدوي، تشغيل الدورة، صندوق الوارد، استيراد Excel، عرض التقارير |
| مشاهد | قراءة فقط (اللوحة، التقارير، السجلات) |

يمكن تقييد أي مستخدم بأقسام محددة (مثلاً منسق جودة قسم يرى قسمه فقط).

## البيانات

- `data/config.json`: البرنامج، الأقسام ورؤساؤها (بريد/واتساب/Teams)، الوثائق والمواعيد، الإعدادات. محمّل حالياً بجدول **الفصل الدراسي الثاني 1447هـ** (21 وثيقة على 4 مراحل) من ملف الوكالة.
- `data/templates.json`: نصوص الرسائل (قابلة للتعديل من اللوحة). المتغيرات: `{{headName}} {{deptName}} {{phase}} {{fileList}} {{fileCount}} {{deadlineArabic}} {{daysLeft}} {{submittedAtArabic}} {{schedule}} ...`
- `data/state.json`: التسليمات، سجل الرسائل، علامات الإرسال (لا يُرفع إلى Git).
- `data/users.json`: المستخدمون (كلمات المرور مشفّرة بـ scrypt، لا يُرفع إلى Git).

### Excel
- `npm run excel:template` أو زر "تنزيل قالب البيانات": قالب بأوراق (الأقسام، الوثائق، التسليمات، الإعدادات) معبأ بالبيانات الحالية.
- الاستيراد من اللوحة أو `npm run excel:import -- ملف.xlsx [--replace]`: يتعرف على أسماء الأعمدة العربية/الإنجليزية الشائعة (القسم، رئيس القسم، البريد، رقم الواتساب، رقم الوثيقة، الوثيقة، المرحلة، مسؤولية التنفيذ، الموعد النهائي ...).
- التصدير (`npm run excel:export` أو زر "تصدير Excel"): مصفوفة الحالة + **نموذج متابعة تسليم وثائق الجودة** لكل قسم بنفس تنسيق نموذج الوكالة + سجل الرسائل.

## القنوات

### البريد (SMTP)
Office 365: `smtp.office365.com` منفذ 587 (يلزم تفعيل SMTP AUTH للحساب). Gmail: `smtp.gmail.com` مع App Password.
لرصد التسليم من الوارد فعّل `IMAP_ENABLED=true` (Office 365: `outlook.office365.com` منفذ 993).

### Microsoft Teams
الطريقة المعتمدة: **Workflow Webhook** لكل قسم:
1. في Teams افتح محادثة/قناة القسم ← ⋯ ← **Workflows** ← "Post to a channel when a webhook request is received" (أو "Send webhook alerts to a chat").
2. انسخ رابط الـ Webhook وضعه في حقل "Teams Webhook" للقسم في تبويب الأقسام.
3. إن لم يُضبط Webhook يوفّر النظام **رابط فتح محادثة Teams مع رئيس القسم والنص جاهزاً** للإرسال بضغطة واحدة (في سجل الرسائل).

### WhatsApp
- `WHATSAPP_PROVIDER=meta`: WhatsApp Cloud API (يلزم Phone Number ID وAccess Token؛ للرسائل خارج نافذة 24 ساعة يلزم قالب معتمد ضعه في `WHATSAPP_TEMPLATE_NAME`).
- `WHATSAPP_PROVIDER=twilio`: Twilio WhatsApp.
- بدون مزود: يوفّر النظام رابط `wa.me` بالنص جاهزاً للإرسال اليدوي.

اختبر الإعدادات من **الإعدادات ← اختبار الإرسال** أو `npm run test:channels`.

## الجدولة

أثناء تشغيل `npm start` يفحص النظام كل 10 دقائق ويُنفّذ الدورة اليومية مرة واحدة عند بلوغ **ساعة الإرسال** (افتراضياً 8 صباحاً بتوقيت الرياض، أيام الأحد–الخميس)، ويفحص صندوق الوارد كل `IMAP_POLL_MINUTES`. إن كان الخادم متوقفاً وقت الإرسال تُنفَّذ الدورة عند التشغيل التالي (تعويض تلقائي).

بديل بدون خادم دائم: شغّل `npm run tick` يومياً من Task Scheduler (Windows) أو cron.

أوامر مفيدة: `npm run preview` (ما سيُرسل اليوم)، `npm run inbox` (فحص الوارد)، `npm test` (اختبارات المحرك).

## ملاحظات مهمة
- التواريخ في `config.json` مأخوذة من جدول الوكالة **للفصل الدراسي الثاني 1447هـ**؛ عدّلها للعام الجديد من تبويب "الوثائق والجدول الزمني" أو باستيراد Excel.
- تاريخ بداية العمل (`2026-02-01`) تقديري لبداية الفصل؛ عدّله من الإعدادات.
- لإعادة إرسال رسالة سبق إرسالها (مثل الانطلاق) احذف علامتها من **الإعدادات ← إعادة الإرسال**.
- الشكر يُرسل عند **اكتمال** وثائق الموعد قبل انتهائه. يمكن إرسال شكر يدوي بالوثائق المستلمة حتى الآن من نافذة الخلية.
